How it works:

You must send all siblings that belong to the same parent.
All items in the array must have the same parent_id (or all be null for main categories).
The endpoint enforces this with a check.
It updates display_order exactly as provided.
Orders must be unique and consecutive (or with gaps — gaps are allowed).

Examples:

To reorder main categories → send all main categories (parent_id = null)
To reorder subcategories under "Electronics" → send only the subcategories that have parent_id = electronics_id

You do NOT send the entire tree at once.
You reorder one level at a time.
This is safe, simple, and works perfectly for most admin panels (e.g., drag-and-drop within a list of siblings).
Pros of This Approach

Simple and atomic
No risk of breaking other levels
Easy to implement drag-and-drop (e.g., using SortableJS, React Beautiful DnD)
Matches your DB constraint: UNIQUE(parent_id, display_order)

Categories in a Hotel/Restaurant POS System (Point of Sale)
In a hotel or restaurant app, categories are used to organize the menu items (food & beverages) that customers can order via the POS system.
You have a two-level hierarchy:

Main Categories → Broad groups (visible as tabs or sections in the menu)
Sub Categories → Specific groups under a main category (items listed inside that section)

Real-World Example in a Hotel Restaurant Menu
Imagine your hotel restaurant menu looks like this on the POS tablet or customer-facing digital menu:
textAppetizers          → Main Category #1
├── Soups           → Subcategory
├── Salads          → Subcategory
└── Starters        → Subcategory

Main Courses        → Main Category #2
├── Indian          → Subcategory
├── Chinese         → Subcategory
├── Continental     → Subcategory
└── Italian         → Subcategory

Beverages           → Main Category #3
├── Mocktails       → Subcategory
├── Juices          → Subcategory
├── Soft Drinks     → Subcategory
└── Hot Beverages   → Subcategory

Desserts            → Main Category #4
├── Ice Creams      → Subcategory
└── Cakes           → Subcategory
The order of main categories and their subcategories matters a lot because:

It controls the visual layout on the POS screen (waiters select quickly)
It affects the customer-facing digital menu or printed menu
Chefs/kitchen often prioritize based on section order

How Reordering Works in Practice (with the /reorder API)
You reorder one level at a time, and you must send all items in that group.
Case 1: Reorder Main Categories (Top-Level Tabs)
The admin wants to change the order so that Beverages appear first (common in hotels — guests often order drinks first).
Current order:

Appetizers
Main Courses
Beverages
Desserts

Desired new order:

Beverages
Appetizers
Main Courses
Desserts

API Request:
httpPOST /api/categories/reorder

[
  { "id": "bev-main-uuid", "display_order": 0 },
  { "id": "app-main-uuid", "display_order": 1 },
  { "id": "mc-main-uuid",  "display_order": 2 },
  { "id": "des-main-uuid", "display_order": 3 }
]
Note: All these have parent_id = NULL → they are main categories.
After this call:

On POS screen, the tabs now show: Beverages → Appetizers → Main Courses → Desserts

Case 2: Reorder Subcategories Under "Beverages"
Now the manager wants to rearrange inside the Beverages section.
Current:

Juices
Soft Drinks
Mocktails
Hot Beverages

Desired:

Mocktails (promoted — signature items)
Juices
Soft Drinks
Hot Beverages

API Request:
httpPOST /api/categories/reorder

[
  { "id": "mocktail-sub-uuid", "display_order": 0 },
  { "id": "juices-sub-uuid",   "display_order": 1 },
  { "id": "soft-sub-uuid",     "display_order": 2 },
  { "id": "hot-sub-uuid",      "display_order": 3 }
]
Note: All these have the same parent_id = the UUID of "Beverages" main category.
After this:

When waiter taps "Beverages" tab → sees Mocktails first

What You Cannot Do in One Call
You cannot mix main and subcategories in the same reorder request:
❌ Invalid request (will be rejected):
JSON[
  { "id": "appetizers-main", "display_order": 0 },
  { "id": "soups-sub",       "display_order": 1 }   ← different parent!
]
→ Error: "All categories must have the same parent"
Why This Design is Perfect for POS

Fast & Reliable: Waiters need quick access — predictable order is critical
Admin-Friendly: Manager can drag-and-drop main tabs separately, then go into each and reorder items inside
Safe: No risk of accidentally mixing levels or breaking the menu structure
Scalable: Even if a main category has 30 sub-items (e.g., "Bar Menu"), you just load and reorder those 30

Typical Admin Panel Flow

Admin logs in → sees list of Main Categories with drag handles
Drags to reorder → frontend sends /reorder with all main categories
Clicks into "Beverages" → sees list of subcategories
Drags to reorder → sends another /reorder with only those subcategories

This is exactly how popular POS systems like Toast, Square, Lightspeed, or Petpooja handle menu organization.
